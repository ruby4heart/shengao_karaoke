# 0.4.1 运行错误与顶框修复

## 原因与改动

0.4 主程序向 wxMSW 的非阻塞标准输入管道一次性写入整份 JSON，随后立即关闭输入。请求超过空闲容量时，Write 可以返回 0 字节；旧代码没有核对 LastWrite，后台收到空任务，JSON 解码异常又发生在原有任务错误处理之外，因而没有 result.json。

本机复现采用合成的 35 行日语歌词：应发送 4644 字节，实际发送 0 字节，后台退出代码为 1，异常为 JSONDecodeError。记录见 `build/fix-repro-test.log` 及 `tmp/native-integration-日语-l459eknf/worker-pipe-reproduction.txt`。用户两次失败记录均为 35 行歌词，只有 task.json，没有后台进度或结果，符合这一失败路径。

- 主程序保留尚未发送的数据，每次按管道实际写入字节推进，空间不足时在后续事件周期继续，完整发送后才关闭输入。UI 保持响应。
- 后台入口覆盖导入与请求解码错误，返回安全的错误结果和进度；不打印请求、密钥或异常原文。
- 主程序记录退出代码、应发 / 实发字节与安全的错误分类，可在任务记录查看；失败后解除忙碌状态。不会自动重新提交云端请求。
- 重新计算自绘窗口的非客户区，消除深色顶栏上方的白色系统边带；保留八个方向的缩放、顶栏拖动和最大化 / 还原，最大化限制在显示器工作区。

## 验证

使用真实主程序的 wxProcess 启动后台，测试 35 行日语本地匹配、300 KB 请求分批送达、失败返回与按钮恢复。普通及最大化窗口直接检查客户区与窗口 / 显示器工作区坐标，并继续执行原有字幕、播放与四阶段布局回归。

后台测试和独立运行包覆盖空输入、截断 JSON、无效 UTF-8，确认均有错误结果且不泄露密钥。发行前检查完整包、源码、依赖和压缩包一致性。

本轮未使用 Computer Use，未读取 API 密钥，未上传用户歌曲，未发起真实付费 API 调用。线上账户权限、配额与识别准确度仍需用户实际使用验证。

## 使用
