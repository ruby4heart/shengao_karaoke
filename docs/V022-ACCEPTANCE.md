# 声稿 0.22.0：按声音检查空白

对应完整 ToDo 第 3 组第六项。先查看人声连续性和保留的歌声音素依据，逐项试听后处理多余间隔，避免仅因间隔短就填平实际停顿。

## 操作与保护

校准页点 **检查空白…**，选择这一句、选中多句、从这里到结尾或整首。默认本句；可先准备人声辅助。分析与试听使用所选原声／人声，不调用云端或重新运行歌声模型。分析长度上限只限制检查量，不是填平阈值。

审核列出建议延续、低能量／声音不明确、依据不足及已保护的边界。逐项带前后音试听，选择保留、声音延续或人工延续，再采用。**去这处校准** 跳回对应词组／音节，不先改时间。稍后处理和任务记录保留结果。

声音延续只延长前一高亮的尾部，下一音节起点保持，结果仍属待核对估算。人工延续明确记录为人工调整；两者都不自动确认读音或时间，可一步撤销。原文、假名、罗马音、原始音素依据保持。人工、锁定、已确认及已有声学边界受保护；非相邻选中句不跨过中间歌词连接。

低能量先保留，不称为已确认语言休止；原声伴奏持续而没有对应音素依据时也保留。TIFA 边界只在素材／音轨指纹、读音和原始音素范围对应时作为依据，不证明假名正确或逐音起点准确。人声分离残留和实际无声辅音仍需试听。

新自动初稿默认保留间隔。原固定时长收拢移至进阶选项，独立开关默认关闭；旧版显式任务参数和未改写的检查点保持原含义。素材内容 SHA256 在分析和采用前后核对；即使大小和修改时间相同，缓存也按真实内容重新生成。若播放缓存与文件内容不同，视频源菜单可 **重新载入当前源（保留字幕）** 后再检查。

结构回归覆盖真实低能量区间、持续元音、噪声、原声伴奏保留、人工／声学保护、非连续选句、取消、结果完整性、素材同大小同时间变化、PCM 损坏、迟到编辑、精确手工跳转、一次撤销及保存重开。流式上传使用真实 HTTP 文件发送路径测试分块及字节一致性，不发网络请求。

离屏桌面自检复用本次先前实际推理得到的 PJS056 三句 37 摩拉，只在一个保留元音内人为制造 40ms 空隙，验证实际 PCM 检查、只读审核、试听、采用、保存、撤销和手工定位；两个自然句间停顿保留。不新增推理／API。公开单一样本、未知训练重合，不宣称一般准确率。

指定 Emerald MV 在副本的 10 处保留元音内各加入 40ms 人为空隙，再使用实际人声音轨检查。10 处恢复、其他音节边界与全部后续起音不变，原始 0.20.0 的 35 句结果保持。该测试验证受控缺陷的处理，不是整首歌词、读音或自然边界人工精度测量。

最终全量、开发版／正常与 150% 独立包、原版像素对照、依赖及归档结果以 `build/desktop-final-audit-v022.json`、`build/v022-evidence` 和 `dist/SHA256SUMS-0.22.0.txt` 为准；不存在这些通过记录时不视为正式交付。未使用 Computer Use、用户密钥或真实付费 API。模型继续限个人非商业用途。

冻结复测曾在增强尾音试听后关闭窗口的原生 `stop` 中阻塞，保留当时线程栈与进程记录。另用受控信号重现旧位置／时长通知在播放器调用返回前直接运行；现将位置、时长、状态、速率、错误及增强试听通知统一改为明确的 Qt 槽与排队连接，清空后丢弃迟到通知。关于线程执行位置的依据见 [Qt 官方说明](https://doc.qt.io/qtforpython-6/tutorials/basictutorial/signals_and_slots.html#thread-affinity)。受控通知回归和同机连续 30 次真实增强试听、停止、源清空及窗口销毁通过；最终全量与独立包须在修正后重跑。这是对已观察路径的修复与验证，不宣称覆盖所有 Windows 解码器问题。

换轨回归还检查迟到位置与加载中的显式定位：旧通知及计时器不覆盖新定位，静音取帧等到目标帧再暂停，并恢复准确的试听播放点。事件记录曾重现“载入时预览目标为 0，用户改到 2400ms 后仍回跳 0”的问题，现随新定位同步更新取帧目标；真实原声／人声切换回归通过。三种最终运行方式保留 `vocal-ab-state.json`，记录预期／实际播放点、速度、缩放与静音；这不能代替全片同步与性能验收。

重复换轨还捕获了元数据已经就绪、但其界面通知尚未执行时的新定位：新的 2400ms 请求必须同时替换旧的待定位 0ms，否则排队的载入处理会把它重置。现按该顺序增加受控回归并保留失败事件记录。

通知改进后，全量压力中仍捕获另一处停止阻塞。Windows 原生线程栈确认主线程在 `QMetaObject::disconnect` 等待 Qt 互斥，后台销毁路径在 `Shiboken/PyGILState_Ensure` 等待 Python GIL。核对本机 PySide6 6.12 的类型系统与受控原生阻塞实验后，播放、暂停、停止统一通过公开 `QMetaObject.invokeMethod` 在所属界面线程同步执行，等待期间释放 GIL；清空媒体和后续销毁仍按顺序完成。新增回归在原生槽返回之前检查 Python 工作线程确实能够运行，并拒绝从其他线程直接控制播放器。保留原生诊断代码、原始栈与两种实际关闭路径的重复记录；最终回归以这些修正后的发行证据为准。
