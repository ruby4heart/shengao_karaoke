# 0.30 本机代理与性能验收标准（测量前固定）

代理用于编辑预览，原唱／伴奏仍是工程的交付源，原声／人声仍是校对音轨。保存、转录和压制不得把代理路径当原素材。默认使用原片；用户明确准备或切换轻量预览，失败或取消继续使用可用素材。

## 代理完整性

- 最大 1280×720，不放大小片源；保留宽高比与逐帧时间。使用现有运行包的 FFmpeg 和 CPU H.264，不增加系统依赖。
- 原片和代理逐帧数量相同，逐帧时间差不超过 1ms；不能用重新指定固定帧率掩盖丢帧或变速。音频统一解码为原采样率／声道的 S16 PCM，样本总数及 SHA256 相同，声音开始与结束时间差不超过 2ms。
- 同时记录原片和代理时间区间、校验指纹、帧数、音频样本、缩放尺寸和生成参数。视频首次／最后位置与三个中间位置在真实播放器检查，指定 MV 的 AV1／Opus 及合成的可变帧率、起始偏移另测。
- 补充旋转显示方向、镜像和非方形像素的实际对照；不能只比较编码宽高，就宣称显示宽高比一致。代理归一方形像素并将方向烘焙进画面，偶数尺寸取整产生的宽高比误差不得超过2个输出像素；实际图像的方向、四角颜色和字幕核心像素另行核对。
- 仅在全部核对后原子发布缓存；取消终止子进程，未完成文件不冒充可用结果。根据原片完整指纹、FFmpeg 指纹和缓存版本复用；再次采用仍检查文件内容。变更源、同路径替换、缓存损坏或工程变更不得套旧结果。
- 切换保持当前播放点、速度、循环范围、音量及原片缩放基准；播放／暂停状态保持。代理任务期间的人工编辑保留。人声试听启用时明确保持其校对音轨，不能无提示换成原声。

时间戳处理依据 [FFmpeg 官方选项说明](https://ffmpeg.org/ffmpeg.html)：生成和验证使用同一输入起点处理，保留帧时间并关闭额外的负时间戳平移；实际逐帧与音频核对决定是否可采用，不能只凭命令参数宣称同步。

## 本机性能目标

测量记录 CPU、逻辑核数、物理内存与可用内存、Windows、软件／媒体指纹、DPI、线程限制和缓存条件。先记录以下目标，再测；不因结果不达标而放宽。受限线程和内存压力条件另外注明，结果不代表其他电脑或干净 Windows。

| 场景 | 测量方式 | 目标 |
| --- | --- | --- |
| 独立包启动 | 新进程到完整窗口可处理操作；分别冷／热缓存各三次 | 热启动 ≤10s，首次冷启动 ≤20s |
| 长工程切句 | 1000 句带词组、注音与音节，连续切换 50 次 | 操作到选中内容和时间轴就绪 p95 ≤250ms |
| 拖轴 | 原版可见音频范围中连续移动／调边界；记录 GUI 响应 | p95 ≤50ms，提交 ≤250ms |
| 试听 | 从按钮到播放器开始前进，冷／热定位分开 | 热定位 p95 ≤500ms；首次解码 ≤3s |
| 大视频／代理 | 指定 4K MV 及 720p 代理相同区间、速度和窗口 | 代理正常速度稳定播放；随机定位 p95 ≤500ms，不出现累积音画漂移 |
| 后台交互 | 生成代理／声音任务期间 20ms GUI 心跳与实际切句 | 心跳间隔 p95 ≤150ms，最长 ≤500ms；普通编辑可继续 |

这是正式版前的本机目标，不是已通过的结果。代理耗时、缓存大小、失败恢复、原片与代理资源占用照实记录；实际效果与保留的完整原片输出一起核验。达不到目标时修正实现或明确保留待办，不能用少量静态标签替代实际长工程或视频。

## 当前源码的可重复测量

使用 `.venv-desktop\Scripts\python.exe scripts/measure-preview-performance.py --source "本机素材路径" --output "新的本机记录目录" --cache-label "实际缓存条件" --with-proxy`；输出目录须不存在，历史记录不会覆盖。按发行测试的线程环境运行，分别注明 `QT_SCALE_FACTOR=1` 或 `1.5`。素材与测量只保存在本机。

脚本记录源码与 FFmpeg 指纹、素材完整指纹、Windows、CPU、可用内存、DPI及线程环境；构造1000句／3000词／7000音节的受控压力工程，测量50次下一句、50次实际列表点击、50次真实拖动、包含字幕更新的提交、随机视频定位和试听开始。可选代理测量在新应用缓存中生成V2，期间用20ms心跳记录事件循环，并继续切句、启用每秒自动恢复保存。所有原始延迟、未匹配帧、失败及未通过目标都进入报告，不以平均值覆盖长尾。

该脚本是源码态测量入口，系统缓存未强制清除；缓存标签必须据实填写。它不代替独立包冷／热启动、持续播放、外部声画感知、正式歌词精度或完整1.0验收。仅脚本内已测目标通过时也仍保留其他待验收项。

## 界面垃圾回收的约束

2026-10-26只读回调诊断确认全代回收可占用编辑中的130–400ms。新策略须同时用于实际入口、开发／独立包自检及性能脚本，不能仅为测量关闭回收。保留第0／1代自动回收和引用计数；第2代在最后一次操作后空闲1秒检查，连续操作时最多等待60秒，持鼠标拖动时继续等待松开。每次完整回收的耗时及回收数量进入本机报告，仍计入事件循环延迟；原有性能门槛保持。

须验证真实循环对象能回收，显式输入、编辑与定位能推迟回收，持续操作有兜底，退出恢复原设置，且不覆盖其他代码修改的阈值。记录完整测量前后可用内存和周期回收，最终还需长时间编辑／关闭场景。策略仅启用在当前固定的CPython 3.12；未来运行时须重新核对。接口语义依据 [Python 3.12 官方GC文档](https://docs.python.org/3.12/library/gc.html)。
