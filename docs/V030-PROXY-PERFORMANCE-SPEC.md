# 0.30 本机代理与性能验收标准（测量前固定）

代理用于编辑预览，原唱／伴奏仍是工程的交付源，原声／人声仍是校对音轨。保存、转录和压制不得把代理路径当原素材。默认使用原片；用户明确准备或切换轻量预览，失败或取消继续使用可用素材。

## 代理完整性

- 最大 1280×720，不放大小片源；保留宽高比与逐帧时间。使用现有运行包的 FFmpeg 和 CPU H.264，不增加系统依赖。
- 原片和代理逐帧数量相同，逐帧时间差不超过 1ms；不能用重新指定固定帧率掩盖丢帧或变速。音频统一解码为原采样率／声道的 S16 PCM，样本总数及 SHA256 相同，声音开始与结束时间差不超过 2ms。
- 同时记录原片和代理时间区间、校验指纹、帧数、音频样本、缩放尺寸和生成参数。视频首次／最后位置与三个中间位置在真实播放器检查，指定 MV 的 AV1／Opus 及合成的可变帧率、起始偏移另测。
- 补充旋转显示方向、镜像和非方形像素的实际对照；不能只比较编码宽高，就宣称显示宽高比一致。代理归一方形像素并将方向烘焙进画面，偶数尺寸取整产生的宽高比误差不得超过2个输出像素；实际图像的方向、四角颜色和字幕核心像素另行核对。
- 仅在全部核对后原子发布缓存；取消终止子进程，未完成文件不冒充可用结果。根据原片完整指纹、FFmpeg 指纹和缓存版本复用；再次采用仍检查文件内容。变更源、同路径替换、缓存损坏或工程变更不得套旧结果。
- 切换保持当前播放点、速度、循环范围、音量及原片缩放基准；播放／暂停状态保持。代理任务期间的人工编辑保留。人声试听启用时明确保持其校对音轨，不能无提示换成原声。

时间戳处理依据 [FFmpeg 官方选项说明](https://ffmpeg.org/ffmpeg.html)：生成和验证使用同一输入起点处理，保留帧时间并关闭额外的负时间戳平移；实际逐帧与音频核对决定是否可采用，不能只凭命令参数宣称同步。

## 本机性能目标

测量记录 CPU、逻辑核数、物理内存与可用内存、Windows、软件／媒体指纹、DPI、线程限制和缓存条件。先记录以下目标，再测；不因结果不达标而放宽。受限线程和内存压力条件另外注明，结果不代表其他电脑或干净 Windows。

| 场景 | 测量方式 | 目标 |
| --- | --- | --- |
| 独立包启动 | 新进程到完整窗口可处理操作；分别冷／热缓存各三次 | 热启动 ≤10s，首次冷启动 ≤20s |
| 长工程切句 | 1000 句带词组、注音与音节，连续切换 50 次 | 操作到选中内容和时间轴就绪 p95 ≤250ms |
| 拖轴 | 原版可见音频范围中连续移动／调边界；记录 GUI 响应 | p95 ≤50ms，提交 ≤250ms |
| 试听 | 从按钮到播放器开始前进，冷／热定位分开 | 热定位 p95 ≤500ms；首次解码 ≤3s |
| 大视频／代理 | 指定 4K MV 及 720p 代理相同区间、速度和窗口 | 代理正常速度稳定播放；随机定位 p95 ≤500ms，不出现累积音画漂移 |
| 后台交互 | 生成代理／声音任务期间 20ms GUI 心跳与实际切句 | 心跳间隔 p95 ≤150ms，最长 ≤500ms；普通编辑可继续 |

这是正式版前的本机目标，不是已通过的结果。代理耗时、缓存大小、失败恢复、原片与代理资源占用照实记录；实际效果与保留的完整原片输出一起核验。达不到目标时修正实现或明确保留待办，不能用少量静态标签替代实际长工程或视频。

## 当前源码的可重复测量

使用 `.venv-desktop\Scripts\python.exe scripts/measure-preview-performance.py --source "本机素材路径" --output "新的本机记录目录" --cache-label "实际缓存条件" --with-proxy`；输出目录须不存在，历史记录不会覆盖。按发行测试的线程环境运行，分别注明 `QT_SCALE_FACTOR=1` 或 `1.5`。素材与测量只保存在本机。

脚本记录源码与 FFmpeg 指纹、素材完整指纹、Windows、CPU、可用内存、DPI及线程环境；构造1000句／3000词／7000音节的受控压力工程，测量50次下一句、50次实际列表点击、50次真实拖动、包含字幕更新的提交、随机视频定位和试听开始。可选代理测量在新应用缓存中生成V2，期间用20ms心跳记录事件循环，并继续切句、启用每秒自动恢复保存。所有原始延迟、未匹配帧、失败及未通过目标都进入报告，不以平均值覆盖长尾。

源码脚本与独立包的`--preview-performance-test`现在共用同一个测量主体；门槛、工作量、恢复与回收策略保持。系统缓存未强制清除，缓存标签必须据实填写。压力测量之外的启动、持续播放、外部声画感知、正式歌词精度和完整1.0仍分别验收。

新构建的冻结包支持：

```powershell
shengao-karaoke.exe --preview-performance-test --source "本机视频路径" --output "不存在的本机记录目录" --cache-label "实际缓存条件" --with-proxy --native-hidden
```

冻结测量前后逐文件核对清单中的大小与SHA256，并拒绝遗漏、额外文件、重复路径和越界路径。输出放在运行包之外，防止把私人任务资料混入发行目录。完整哈希读取会温热文件缓存，报告如实记录；源码态保留完整来源快照，冻结态保留实际运行包清单指纹，不把不适用的源码检查记为通过。旧0.29和此前的内部包不具有此新入口。

启动使用`scripts/measure-desktop-startup.py --package "新运行包目录" --output "不存在的本机记录目录" --scale 1`。三个空应用目录与三个复用应用目录分别使用新进程，20秒／10秒门槛不变；外部启动计时包含解释器与程序导入，到完整窗口实际绘制并响应两次可还原的鼠标操作。目录、DPI、原始时间与完整性核验均保留。此工具没有清理系统缓存，完整哈希审计会温热文件；空应用目录与复用应用目录的六次结果单列，系统冷缓存与干净Windows验收继续保留，不借此提前完成11.2或11.1。

## 界面垃圾回收的约束

2026-10-26只读回调诊断确认全代回收可占用编辑中的130–400ms。新策略须同时用于实际入口、开发／独立包自检及性能脚本，不能仅为测量关闭回收。保留第0／1代自动回收和引用计数；第2代在最后一次操作后空闲1秒检查，连续操作时最多等待60秒，持鼠标拖动时继续等待松开。每次完整回收的耗时及回收数量进入本机报告，仍计入事件循环延迟；原有性能门槛保持。

须验证真实循环对象能回收，显式输入、编辑与定位能推迟回收，持续操作有兜底，退出恢复原设置，且不覆盖其他代码修改的阈值。记录完整测量前后可用内存和周期回收，最终还需长时间编辑／关闭场景。策略仅启用在当前固定的CPython 3.12；未来运行时须重新核对。接口语义依据 [Python 3.12 官方GC文档](https://docs.python.org/3.12/library/gc.html)。

## 连续编辑和实际呈现（扩展测量前固定）

在原1000句场景连续完成50次真实边界拖动与提交，每次保留一条撤销记录；仍以每次完整提交≤250ms评估，完整原始数组和p95／最长同时保存。之后逐步撤销、重做，再还原原工程，逐字段核对；不能用一次较快提交代表连续操作。

本进程私有提交内存相较连续操作前的增长预算为256MiB，提交和撤销／重做均采样。超过预算时停止新增压力提交、保留已经测到的结果并标记未完成50次，不能把提前结束记为通过。记录工作集、峰值工作集、私有提交和缺页数，系统可用内存另列；两者不混称。查询使用Windows官方 [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo) 与 [PROCESS_MEMORY_COUNTERS_EX](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)，只查询自己的进程。

视频定位与试听时使视频完整可见，核对Canvas实际绘制完毕的新帧及PTS；解码回调另存诊断，不能代替呈现完成。首次解码与首次实际画面分别记录，均按3秒门槛检查。视频定位保持原500ms门槛；首尾／中间帧、持续播放与独立包启动仍须补齐。这些新增记录不将旧的回调测量改称呈现测量。

## 自动恢复不得阻断连续编辑

完整场景的阶段诊断发现同步自动恢复写入占用约108ms，叠加于一次改轴后；诊断不作为验收延迟。定时恢复改为GUI线程取得完整独立快照，再由本机工作线程完成JSON序列化、写入和文件同步。快照获取仍计入GUI耗时，后台线程不读取活动工程或活动API结果。

每个写入带代号，最后替换恢复文件前必须再次核对；失效检查与最后重命名共用短锁，序列化、磁盘写入和重试等待在锁外。最新待办覆盖旧待办，同时最多一个后台写入。清理、换工程、手动保存和关闭须让旧任务失效；过期失败不覆盖新状态，过期成功不重建已清理文件。显式检查点与正常退出继续同步保证当前记录已落盘。写入失败保留上一份恢复文件，在GUI线程提示；临时目标不能冒充已完成检查点。

完整性能复测继续沿用原50次提交、250ms上限和256MiB增长要求；代理期间保持每秒定时恢复与20ms心跳。不能通过关闭自动恢复或仅在基准程序中改用后台写入取得通过。

成功编辑在同一次同步事务中已有完整独立快照时，纯JSON记录可交给后台恢复写入，内部消费者仅保留只读引用。约一秒内的连续动作合并为最新快照，同时重新开始原15秒定时器，避免刚编辑完又复制整份相同工程；已完成工作在后台释放，不把整份文档留到GUI完成回调。该路径须覆盖真正编辑、后台合并、最新结果与撤销／重做，不额外读取或序列化活动工程。待审核API结果、不常见Python类型或校验模块不可用时保留原定时新快照；定时入口仍捕获没有经过刷新或编辑入口的直接变化。保存、清理、换工程、关闭及停用自动保存须处理暂存快照与旧任务，显式检查点语义保持。

## 首尾位置与持续播放（新增测量前固定）

原片和已核验代理分别检查首帧、视频区间25%／50%／75%及最后一帧。以逐帧审计的视频区间选点，不用较长的音频尾部代替视频尾帧。每次定位须取得实际绘制的新帧，其PTS区间覆盖目标；记录实际图像尺寸、时间、序号及本地帧图像。代理仍使用原片显示尺寸作为缩放基准，五处原片／代理帧供本地对照，私人MV图像不进入公开验收。

随后在相同1000句工程、原有自动恢复和回收策略下，原片与代理各从首帧按1倍速播放完整素材。以20ms计时器采样播放器时钟与Canvas实际绘制的新帧序号；重复绘制同一帧不计为新视频帧。新帧间隔及播放器时钟与已绘制帧PTS的差值均记录完整数组，p95不超过150ms、最长不超过500ms；时钟误差以当前有效帧的区间计算。准备及定位先独立完成，再开始持续播放计时；实际播放耗时与媒体区间长度之差不超过2秒，结束须到达播放器真实EndOfMedia并保留最后有效视频帧。

记录全部临时停顿、错误、回收、源／代理指纹、缓存和硬件条件；不能删去慢帧、关闭自动恢复或改快播放速度。此项验证本机播放器时钟与实际离屏绘制的连续性，物理声画及真人整首判断仍独立验收。

## 原生Windows GPU路径的单独记录

4K SDR帧增加GPU缩小后回读，显示仍由原Canvas和同一ASS渲染器组合。每次只向私有视频接收器提供指定帧，保持图像和PTS一一对应；最大回读边长1920px。原始尺寸与缩放基准保持，放大检查时恢复完整源帧。未经核对的变换、HDR、元数据或不可用后端使用原Qt图像路径。

该加速需要原生Windows图形后端；Qt的纯offscreen平台默认软件场景图，不能据其黑屏或未进入GPU路径宣称实际GPU性能。新增`--native-hidden`场景使用Windows Qt和不显示到屏幕的自有窗口，执行相同1000句、50次提交、完整撤销／重做及代理任务，所有数值门槛保持。记录平台与实际加速状态；旧offscreen结果独立保留，不改称通过，也不从两种平台挑选较快项目拼成一轮。正常／150%隐藏原生实例须另验实际颜色、字幕核心像素、PTS、缩放与CPU回退；新的独立包也须验证加速模块完整。

持续播放入口为`desktop/main.py --playback-continuity-test --source ... --output ... --proxy-cache ...`，冻结包使用同名参数。缓存先由同一代理实现核验，准备时间独立于持续播放；是否复用必须记录。五处定位使用带目标位置的静止首帧预览，另有十次普通随机定位压力项，两者不混称。完整播放的正常15秒后台恢复须有实际落盘／重新加载断言。阶段进度只用于观察，以最终报告为准。
