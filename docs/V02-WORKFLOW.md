# 0.2 工作流改进与验收

本轮目标：补充实际制作需要的功能，修正现有问题，重做现代化工作流界面。保留原生视频、频谱和卡拉 OK 时间轴；不操作用户桌面，不调用真实付费服务。

## 实现要求

1. 将长侧栏改为“导入、校轴、注音、交付”四个阶段，保留固定的当前行信息、未保存提示、任务进度与取消入口。阶段切换不能丢失编辑。统一浅色背景、留白、按钮层次和表格样式。
2. 增加媒体打开入口、LRC 文件导入，并让拖入 JSON/LRC 与相应打开操作一致。LRC 支持多时间标签、毫秒及 offset；非法文件不能破坏当前工程。
3. 增加字幕检查，识别无音节时间、估算时间、零时长、重叠、缺少读音和未确认状态；支持定位问题与下一待校准行。
4. 增加所选行／全部歌词的批量时间偏移，保持音节、注音和静音间隔一致；负时间整批拒绝，操作可撤销。
5. 增加任务历史和成功结果恢复，失败详情可查看；历史恢复不重新请求云端，结果仍需审核，已更改／锁定／不唯一匹配的歌词受到保护，防止识别结果重复追加。任务元数据只保存明确允许的字段，绝不保存密钥。
6. 修复只改译文或罗马音时重写 ASS 样式标签的问题；修复同一假名的不同拆分错误复用旧边界的问题；时间改动要取消旧的人工确认状态，保持人工锁定信息。
7. 预览标识当前状态，修改文档后明确提示刷新，避免误把旧的注音预览当作最新成品。
8. 编译并验证真实原生流程；生成新版本程序、使用说明、源码及校验文件。原版目录及 0.1 正式包保留。

## 验收

- 对 LRC、检查规则、批量偏移和歌词匹配保护执行有意义的边界测试。
- 使用真实编辑器服务验证新功能、撤销、保存重开、现有 API 审核保护和字幕渲染。
- 通过软件自身的离线渲染／布局产物检查四阶段界面，并验证窄窗口布局。
- 对完整包检查独立运行、依赖、中文路径、导出、安装、源码一致性和压缩包完整性。
- 真实云端账户调用仍不在开发验收中冒充成功。

## 交付与界限

运行包目录为 dist/ShengaoKaraoke-0.2.0-final-win64，对应同名 ZIP；源码包为 dist/ShengaoKaraoke-0.2.0-source.zip。完整包检验包括哈希、独立后台、中文路径、自带 FFmpeg 提取 / 渲染、四种导出和隔离安装，记录在 build/package-test.log。档案 CRC、源码 / 二进制一致性与 DLL 检查见 build/release-check.log，校验值在 dist/SHA256SUMS-0.2.0.txt。

旧版未保存恢复元数据的任务不会自动猜测匹配。LRC 以句级粗轴导入，增强 LRC 暂不支持；原生 ASS 时间精度为 10 ms。合唱重叠可以保留，估算时间和特殊唱法仍需试听。0.5× / 0.75× 慢放会变调，成品默认 1920×1080。

真实 ElevenLabs、MAI、DeepSeek 账户未进行付费调用；接口契约使用回环 HTTP，媒体使用合成素材。此限制不会被本地通过的测试替代为真实账户成功记录。
