# 新手工作台与熟练操作：第7组实施规格

计划组名0.31，正式版本号以最终发行审计为准；0.30六项功能及GitHub四份附件已交付。本组一起推进ToDo第7组七条，正式版主待办仍为35条。共用状态、准备页／顶部导航、真实确认进度及键位设置与运行时已接入；第一轮42项通过，修正重复入口后62项专项通过，后续正常／150%各56项快捷键与焦点专项通过。跟唱打点、可选预览设置、更多音乐对照和整组发行验收尚未完成；见[V031开发验收](V031-ACCEPTANCE.md)。

目标是让没有用过Aegisub的人知道现在完成了什么、下一步能做什么，同时保留熟练用户的音频操作。现有工程格式14、原文、读音、人工轴、确认、三状态颜色、歌名／歌手、代理和原唱／伴奏切换继续保持。

## 1. 一个状态来源，五步提示一致

页面标题、主要按钮、顶部下一步和进度共用同一份工程状态判断，不分别维护提示字符串。保存状态与读音／时间确认分别显示，AI初稿和人工确认不混计。

| 已有资料／状态 | 主要操作 | 同时保留的入口 |
| --- | --- | --- |
| 没有有效素材 | 添加视频／音频或重新定位 | 离线练习、打开工程 |
| 已有素材，没有原歌词 | 粘贴原歌词 | 识别并核对原文 |
| 有待核对的识别原文 | 继续原文核对 | 采用自己的正确歌词 |
| 有待审核建议 | 继续审核建议 | 回到当前手工编辑；不自动采用 |
| 已有原文，没有词组 | 生成可审核初稿或手工分词 | 本句范围、正确时段匹配 |
| 有未确认时间／读音 | 继续当前或下一个待校对项 | 本句统一编辑、疑点筛选 |
| 全部时间／读音已确认 | 检查样式、样片与导出 | 明确选择的重新生成初稿 |

实际缺陷作为验收：已有素材和两句确认歌词时，导入页不能继续把“先添加素材，再准备歌词／生成初稿”显示成唯一主要方向，并与顶部“生成字幕”相冲突。回到以前步骤允许检查或重做，但须保留继续当前成果的入口。

阶段切换保留播放位置、缩放、试听源和当前行。重新生成是明确动作，沿用审核、人工保护和撤销，不因返回页面自动调用API。确认下一步时不把没有人工确认的记录标成完成。

## 2. 常用动作与进阶选项

五步流程默认收起，已完成状态和下一步可见；进阶工具按需展开。校对页保留大视频、完整音频区、邻句参照和常用播放／确认操作。常用按钮说明动作及对象，悬停显示当前有效快捷键。

统一“保存作品”“确认本句时间”“确认本句读音”“应用本次修改”的含义；保存作品不能代替确认，确认也不能代替保存。弹窗中的预览、应用、取消和回到主编辑区保持明确的事务边界。低分辨率／高DPI下不以隐藏重要按钮取得整齐布局。

按2026-10-29用户要求，性能优化留到最后，先完成本组功能。工作台提供独立的可选预览性能设置：保留已有轻量预览的明确选择，为GPU加速及资源设置增加可关闭／回退的入口；不会要求先完成压力优化才能继续制作。选项的切换与保存验证属于功能验收，延迟达标仍由ToDo11.2在最终阶段独立核对。

## 3. 时间范围与文字

沿用已有统一时间变换入口和模型，显示“这一句”“选中N句”“从这里到结尾”“整首”；作用范围、行数、锁定及固定点冲突在应用前明确。当前选中变化、搜索筛选与跨句选择都更新同一范围来源，不能出现时间轴与右侧说明各指不同对象。

按钮、工具提示、审核说明、快捷键帮助与错误提示逐项对应真实行为。至少覆盖整句移动、内部分界、起止输入、显示留屏、保存和确认；不新增一套与现有撤销不一致的快捷修改路径。

## 4. 可配置键位与输入保护

本机原始依据为用户提供的Aegisub 3.5.0 `src/libresrc/default_hotkey.json`，SHA256：`f69d48ce66d5ebf2201dc98089dfa4b2a1332144fa1cab781960f71451146948`。已核对`Audio`与`Always`上下文及`hotkey.cpp`中Medusa开关对`Always`的启用；现有实现见`desktop/shengao/aeg_hotkeys.py`。

| 上下文 | 保留的默认示例 |
| --- | --- |
| Audio | R整句，S／空格选区，B播放／停止，H停止；Q/W前后500ms，E/D选区首尾500ms，T播到末尾 |
| Audio | A/F滚动，左／Z与右／X切换，C/V引入／引出，Enter/G提交，Shift+G默认方式提交 |
| Audio | 小键盘加减与Shift组合；Ctrl+小键盘乘号开关Medusa |
| Always，用户启用Medusa后 | 小键盘Enter提交、5试听、8停止、1/3前后试听、0/2切换、4/6移动起点、7/9调整长度 |

自定义界面按命令、当前键位、原版默认和作用范围显示；支持搜索、多键位、恢复默认和配置导入／导出。冲突判断考虑同时可激活的上下文，区分主键盘／小键盘和修饰键；不同模式互斥的键不误报为同时冲突。未支持的Aegisub命令须列出，不能导入后悄悄执行另一动作。

文字、时间输入、可编辑组合框、表格编辑器及输入法组合状态均有明确的焦点规则。默认音频上下文键不截获输入。原版Medusa的Always行为是用户明确选择的兼容模式，应清楚标注；已有开启状态迁移保持原意，新增输入保护选择与其区别明确，不能通过改名偷偷改掉用户的键位行为。模态窗口和主窗口上下文分开。

导入先校验和预览：无效文件或无法解决的冲突不改变现有配置；应用一次完成，失败保持旧值。导出仅包含键位和作用范围，不混入API配置。配置版本、键名规范化和未知命令处理有明确规则，软件重新启动后保持。

## 5. 可选跟唱打点

以独立开关／面板进入，退出即恢复普通Aegisub键位。使用现有播放器和原片时间基准，可选择当前原声／人声辅助；不另开一个独立走时的播放器。

在已有词组／音节与明确本句范围上录制边界，显示当前目标和剩余数量。先给出试听区间及录制规则，再开始；支持暂停、退回上一点、重录、停止试听和取消。它是手工打点初稿，不能标成声音模型已经精确识别。实际听感还需要试听校正，不能把播放器时钟当作物理音频输出延迟测量。

打点先留在草稿，显示原边界与新边界，应用时一次撤销；锁定、人工固定点和原有手调按现有规则保护。没有词组或读音时直接引导到对应编辑入口，不凭汉字数量伪造演唱音节。源、行、分词或人工内容在录制期间变化时保留草稿并要求重新核对，不覆盖新工程。

连续边界打点与真实停顿的处理须在面板明确；不能隐式填平所有间隔。模式内快捷键不影响普通文本输入，也不成为默认全局空格行为。

## 6. 更多实际音乐绘图对照

保持原版Aegisub绘图ABI及时间坐标，增加真实歌曲的乐器、主唱、密集副歌、弱尾音和停顿区间。采用同一份解码PCM，核对波形／频谱、三个滑条、缩放／平移、选区与边界。实际歌曲片段、截图和工作工程只留本机；公开证据继续用有权分发的合成素材和脱敏数值。

记录原片、解码、DPI、渲染参数及原版来源指纹。波谱一致不能替代歌词／音节精度或真人使用；操作对照也不能替代当前源码与两档独立包回归。

键位覆盖两种原版上下文、自定义冲突、坏配置、恢复默认、主／小键盘差别、文本与输入法焦点、弹窗以及重启保持。打点覆盖正常、缺点／多点、暂停、取消、锁定、录制中修改与素材变化、应用和撤销。字体／配色／歌名及原唱／伴奏轴均保持。
