# 独立声稿工作台重构

本轮目标来自用户确认的完整方案：新用户无需学习 Aegisub，即可拖入视频、准备原歌词、生成初稿、逐句校准读音和演唱时间、选择字体与样式，并在软件内压制成品视频。不是继续在 Aegisub 主窗口上追加面板。

## 架构与边界

- 新建 `desktop/`，使用 Qt 6 / PySide6 构建独立 Windows 桌面程序；不得依赖 FrameMain、agi::Context 或启动旧编辑器。为满足用户追加的原版时间轴要求，保留 wxMemoryDC / wxGCDC 作为离屏绘图依赖；它不创建 wx 窗口，也不管理工程、输入或工作流。此项替代早期方案中“完全不依赖 wx”的实现选择，产品独立性要求保持不变。
- 自有版本化工程模型记录素材、原歌词、词组、演唱音节、读音、时间、独立的读音／时间确认、样式及字体资源。统一撤销、保存、自动恢复。
- 复用现有 `backend/studio_backend` 的转录、匹配、分词、注音、设置与缓存能力。所有云端结果先审核；人工／锁定数据受保护，不自动重新提交付费请求。
- 独立时间轴和播放交互；可移植的时间算法参考现有声稿模块，保留来源与授权。字幕预览和压制共用 ASS 生成与 libass 渲染。FFmpeg 独立进程执行媒体任务。
- 原始 `E:/transcribe/Aegisub-3.5.0`、原运行包和根目录旧 web 程序不在修改范围。

## 完整验收要求

1. 独立 Qt 主窗口、原生标题栏、可缩放布局、拖放媒体／工程／歌词、离线练习、明确的五步制作流程。主操作可在普通笔记本窗口内发现。
2. 新工程、旧 JSON 和声稿 ASS 工程导入，保存重开不丢原文、词组、读音、手调时间及样式；外部 ASS 的复杂样式与标签有保留机制，不能静默用简化模板覆盖。
3. 实际视频／音频播放与定位、当前句循环、保留音高慢放、可缩放波形、词与音节边界、整句起止、拆合词组、停顿试听及双向合并、确认下一句、撤销重做。
   - 用户追加要求：时间轴需与 Aegisub 原版一致；波形和频谱的易读性对齐原版。必须以原始 3.5.0 的渲染源码、频率映射、FFT、配色、缩放刻度、边界及打 K 交互为依据。同一音频／采样率／质量／增益／缩放下建立对照证据；早期简化波形和灰度频谱不满足要求，不作为完成依据。
4. 编辑即时进入工程；保存文件与自动恢复明确，关闭未保存工程有保护。时间确认与读音确认独立，锁定内容不被自动重做。
5. 原歌词始终权威；离线日语词典、假名及罗马音、ElevenLabs／Microsoft AI 转录与匹配、局部对齐、DeepSeek 建议及转录辅助复核可在新流程中使用。设置沿用 DPAPI，不把密钥写入工程或日志。
6. 样式模板与真实歌词字体推荐，日中字符覆盖检查、可读性、缺字／溢出／注音碰撞提示，原文／假名／罗马音／译文分别可控。内置许可允许分发的默认字体，并能添加本地字体。工程保存字体引用与可携带资源。
7. 统一渲染的实时高亮预览、ASS 输出、十几秒试压和全片 MP4 压制；默认跟随视频分辨率及帧率，实际编码器能力探测、CPU 路径与可选显卡路径。
8. 长任务后台运行、真实进度及预计时间、取消、错误原因、任务记录、可恢复审核结果；压制失败不发布半成品为成功文件。
9. 提供独立可运行包、对应源码、完整授权与中文上手说明。隔离环境验证无需开发 Python／Aegisub。
10. 测试覆盖真实 Qt 控件、媒体播放、手动校准及撤销、工程恢复、字体与渲染一致性、真实试压／压制与失败取消、既有后台回归。不得用纯模型测试代替完整制作验收。尽量不使用 Computer Use；自身测试实例可以离屏渲染。

## 交付顺序

1. 独立技术样机：工程、Qt 窗口、媒体播放、自己的时间轴、libass 字幕画面。
2. 完整离线工作流：素材到校准、样式、ASS 与视频压制。
3. API 与原工程迁移、审核与任务恢复、性能及发行包验收。

上述为同一个完整目标的阶段，不将样机或离线子集视为任务完成。完成时逐项附可核验的源码、运行和产物证据。
