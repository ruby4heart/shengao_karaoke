# 时间轴精度参考测量（ToDo 234 的 PJS056 部分）

测量日期 2026-11-12。引擎 `tifa-1.0-st-mora-cpu-v2`，模型文件和指纹不变。这里只记录用公开人工标注测得的误差，不使用模型自报的分数。Emerald 人工参考音节尚未提供，那一半另测。

## 方法

- 参考答案：程序自带的 PJS056 公开演唱和人工音素标注（CC BY-SA 4.0，来源见 `desktop/assets/alignment-demo/ATTRIBUTION.txt`），共 3 句、37 个摩拉。
- 改前：不加换气／余韵标记，等同于原来的 v1 引擎。改后：当前 v2 引擎，在自由的句首加换气（AP）、自由的句尾加余韵（EP）标记。
- 句子范围两种。“初稿范围”模拟转录粗时间：起点随机偏 ±300 ms，终点偏 −500～+300 ms，再按初稿规则向前外扩 500 ms、向后外扩 1500 ms，不进入相邻句。“手画范围”比歌声宽一点：前 50–200 ms，后 100–400 ms。每句用固定种子随机 20 种范围，所以每种情况 60 句，可重复。
- 声音三种：干声；合成房间混响（约 1.2 秒）；混响加噪（约 0.9 秒、湿声 +3 dB、信噪比 30 dB）。
- 误差＝程序结果 − 人工标注。MAE 是平均绝对误差；“中位偏差”为负表示偏早。
- 句尾检查：对每种情况都运行程序自己的句尾检查（按人声辅助方式），统计它标出的疑点，以及各句尾候选与人工句尾的误差。检查本身不改时间。

## 结论

1. 句首：PJS056 六种情况全部变准，初稿范围 MAE 从 15–24 ms 降到 8–15 ms，和 100 首的结果一致。
2. 句尾：PJS056 原来的句尾本来就准（4–23 ms）。加余韵标记后句尾整体提前，中位约 9–28 ms，MAE 多了 3–16 ms，但 50 ms 内的比例仍有 97–100%。100 首整体看，混响下句尾明显改善（初稿 86 → 63 ms，50 ms 内 62% → 75%），干声略差。也就是说，余韵标记主要解决“句尾拖进混响”，代价是干净录音上句尾平均早几毫秒到十几毫秒。曾考虑加一个固定的句尾补偿，但 100 首里改后中位偏差只有 −11～+6 ms，加噪时还是正值，补偿收益很小，又容易按单首歌过度调整，所以这次不改算法。
3. 句内音节起点：基本不变（相差约 1 ms）。
4. 句尾候选默认保持当前句尾、只供试听，这个设计在 PJS056 上得到印证：没有候选比模型句尾更准。
5. 多方案比对没有在 PJS056 上测量：这个样本没有转录、文字对齐和人声辅助，可比的来源不够。多方案只把方案并列出来由人选择，不自动改时间。
6. 局限：PJS056 只有 1 首 3 句，不能确认是否在模型训练数据里；混响和噪声是合成的，不代表真实 MV 混音。Emerald 需要用户手工校准的参考音节后再按同样指标测量，测完才能勾选第 234 项。
